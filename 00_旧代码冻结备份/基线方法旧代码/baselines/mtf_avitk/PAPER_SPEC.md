Kolmogorov-Arnold network." *Mechanical Systems and Signal Processing*, 228,

Extracted by reading the full text (18 pages, all sections, all tables, all
figures rendered and visually inspected, including Fig. 3's exact architecture
diagram) of `Tool wear state recognition study based on an MTF and a vision
transformer with a Kolmogorov-Arnold network.pdf` shipped in the project root.

the Appendix" reference in §2.3/§2.4 points at the paper's online-only
Supplementary Data (not embedded in the PDF) — not available to this project.

Legend for "Paper status": `Explicit` (paper states the value/formula
directly), `Inferable` (not stated as a number, but uniquely determined by a
formula, an explicit figure diagram, or a named standard architecture
elsewhere in the paper), `Missing` (paper gives no way to derive a unique
value; an implementation choice is made and justified in the same cell).

## 2. Architecture summary (as implemented)

```
Raw force (Fx,Fy,Fz), stable region [90000:100000] per cutting pass
  -> 5 non-overlapping windows of length 2000
    -> F = sqrt(Fx^2+Fy^2+Fz^2)                          (Eq. 8, per 2000-sample window)
    -> Sym7 wavelet decomposition (level 6) + soft threshold + reconstruction (denoise)
    -> MTF encoding: normalize[0,1] -> Q=50 quantile bins -> Markov matrix W [50,50]
                     -> expand to M [2000,2000] by temporal position               (Eq. 1)
    -> resize (area) to 500x500                                                    (paper-stated image size)
    -> colormap (viridis) -> RGB                                                   -> [500,500,3]
    -> resize (bilinear) to 384x384                                                -> [384,384,3]  (ViT input)

Adapt-ViT_L/32:
  [384,384,3] -> Conv2D(1024, k=32, s=32) -> [12,12,1024] -> flatten -> [144,1024]
    -> prepend class token, add position embedding -> [145,1024] -> Dropout
    -> x24 Encoder Block:
         LN -> MHSA(16 heads) -> DropPath -> +residual
         LN -> { MLP: Linear(1024,4096)->GELU->Dropout->Linear(4096,1024)->Dropout ,
                 AdaptMLP-adapter: Down(1024->64)->ReLU->Up(64->1024)->scale(s=0.1) }
              -> summed -> DropPath -> +residual                                    (Eq. 6)
    -> LayerNorm -> extract class token [1,1024]
    -> KAN([1024, 64, 3], G=5, k=3, base_activation=SiLU, scale_base=1.0, scale_spline=1.0)
    -> Softmax -> {Initial, Normal, Severe}
```

## 3. Open questions / conflicts

1. **500×500 vs. 384×384 vs. the underlying 2000-sample signal length.** §2.2 defines the MTF matrix M as `[n,n]` where `n` is literally the length of the (denoised) input 1D signal. Since the primary sub-window length is 2000 (§3.2), the "native" MTF matrix would be 2000×2000. But §3.2 separately states the final images are `500×500×3`, and Fig. 3 states the ViT's own input layer is `384×384×3`. No resize/downsampling step or method is named anywhere connecting these three numbers. We implement two unstated resize steps (2000×2000 → 500×500 via area-interpolation, then 500×500 → 384×384 via bilinear) to honor both explicitly-stated image sizes as checkpoints, but this is a real, unresolved internal inconsistency in the paper, not a clean spec.
2. **Pretrained-weights status is the single largest fidelity risk for Protocol A.** See the dedicated table row above. The paper never states whether ViT-L/32 starts from pretrained weights; this project defaults to ImageNet-21k pretrained + frozen backbone (matching the entire premise of AdaptMLP-style efficient fine-tuning) as a documented inference, not a stated fact. If Protocol A sanity accuracy is far below the paper's 95.38% (B1), this is the first place to investigate.
3. **MTF channel mapping (grayscale-math → RGB image) is unstated**, resolved via a fixed `viridis` colormap chosen to visually match Fig. 9's rendered sample images (which are clearly multi-hued, not 3x-replicated grayscale).
4. **AdaptMLP's exact LayerNorm-sharing between the MLP branch and the adapter branch** is read from Fig. 3's diagram (a single "Layer Norm" box feeding both the "MLP Block" and "AdaptMLP Block" sub-panels) rather than from Eq. (6) alone, which could also be read as each branch having its own independent LayerNorm. Fig. 3 is treated as authoritative here since it is the paper's own explicit architecture diagram.
5. **KAN implementation source is not yet selected** (see table row); will be documented in `baselines/mtf_avitk/README.md` once chosen, per the parent task's requirement to record the KAN implementation provenance and avoid installing untrusted packages without review.
6. **Wavelet threshold-selection rule** (VisuShrink/universal vs. any other) is a genuine gap — the paper names "wavelet threshold denoising" and "soft thresholding" but not which threshold formula computes the numeric threshold value itself; documented as an implementation choice (universal threshold via MAD-estimated noise sigma) in the table above.
